# W5D4 模块1：测试集候选池构建与随机抽样

## 1. 测试集候选池

**为什么需要提前确定测试集：**

测试集用于评估模型对未参与训练和调参的数据的泛化能力。

如果根据模型在测试样本上的表现重新选择测试数据，最终评估指标可能产生选择偏差，无法客观反映模型性能。

因此，需要在模型评估之前预先确定候选池、筛选条件和抽样方法。

**当前数据来源：**

Common Voice Beijing26 zh-CN。

当前 `metadata/manifest.csv` 覆盖该数据集的全部2860条 clips，而 `source_registry.csv` 中之前的38.10分钟属于另外一次抽样登记，不能混为一谈。

manifest 数据规模：

| split | clips |
|---|---:|
| train | 2281 |
| dev | 409 |
| test | 170 |

**当前数据划分检查：**

- train/dev speaker交叉：0；
- train/test speaker交叉：0；
- dev/test speaker交叉：0；
- parent_uid跨集合交叉：0。

当前缺少真实的session_uid，因此不能证明原始录音场次之间完全隔离。

## 2. 测试集抽样

**抽样前的筛选条件：**

1. 只从manifest中 `split=test` 的样本选择。
2. 音频时长满足5–30秒。
3. 样本具有可识别的来源和音频路径。
4. 不根据模型预测是否正确选择样本。

**当前筛选结果：**

原始test样本：

170条。

符合5–30秒条件：

98条。

**采用的抽样方式：**

简单随机抽样（Simple Random Sampling）。

随机种子：

`seed=42`

先固定候选记录的排序，再使用随机数生成器产生一次随机排列。

**为什么需要固定随机种子：**

在输入数据和处理方式相同的情况下，使随机排列结果能够复现。

**为什么需要selection_rank：**

记录每条候选样本在固定随机队列中的顺序。

后续标注不必重新抽样，可以按照预先确定的顺序继续进行。

本次分配：

- selection_rank 1–10：W5D4；
- selection_rank 11–20：W5D5；
- 其余样本：backlog。

---

## 3. 测试集选择偏差

**什么是测试集选择偏差：**

如果根据模型表现、人为偏好或实验结果决定保留哪些测试样本，最终测试集可能不再客观反映预先设定的目标数据分布。

例如：

只选择模型识别错误的样本，可能导致错误率偏高。

只选择模型容易识别的样本，可能导致错误率偏低。

**如何避免：**

- 在查看模型测试结果之前确定候选池；
- 预先设定样本筛选条件；
- 使用固定随机抽样或预先定义的分层抽样方案；
- 保存抽样种子和随机顺序；
- 不根据模型错误重新选择测试样本；
- 测试集冻结后，不因模型指标好坏而调整样本。

需要注意：

随机抽样不一定保证有限样本完全具有代表性。

仍需在后续分析中检查数据分布和测试集覆盖情况。

---

## 4. test_candidates.csv 的作用

**文件位置：**

`metadata/test_candidates.csv`

**文件作用：**

保存测试集候选样本及其人工校对记录。

它不是Common Voice原始提供的文件，而是本项目自行建立的测试集标注工作表。

主要字段包括：

- candidate_uid：候选样本唯一标识；
- selection_rank：随机队列中的顺序；
- review_batch：计划校对批次；
- audio_path：音频路径；
- source_id：数据来源标识；
- parent_uid：原始clip标识；
- speaker_id：说话人标识；
- session_uid：原始场次标识，当前为unknown；
- source_text：原数据集提供的转写；
- raw_text：人工校对后的原始转写；
- score_text：后续用于评估的归一化转写；
- status：人工校对状态；
- uncertain_span：不确定词或片段；
- notes：校对备注；
- review_minutes：实际校对耗时；
- sampling_method：抽样方式；
- sampling_seed：随机种子。

**为什么需要candidate_uid：**

通过唯一标识将候选记录与对应的音频片段关联起来，方便后续校对、追踪和检查重复记录。

**为什么不能直接将候选样本标记为verified：**

因为随机抽样只负责选择样本，并没有进行人工听音。

原始转写可能存在错误或不确定内容，因此所有新抽取的样本应先标记为pending。

只有完成实际听音，并满足人工校对标准后，才能将其标记为verified。

## 6. 当前理解

**为什么要提前固定测试集抽样规则：**

避免根据模型结果或人为偏好选择测试样本，从而减少测试集选择偏差，提高后续评估的可信度。

**为什么固定随机种子：**

使随机排列过程能够复现，方便验证样本是如何被选择出来的。

**为什么随机抽样完成不等于测试集标注完成：**

随机抽样只决定选择哪些音频，不能确认其转写文本是否正确。

人工标注需要实际听音，检查原始转写并记录不确定片段。

**为什么当前不能直接证明严格的场次隔离：**

因为manifest没有可靠的原始录音session_uid。

虽然speaker_id与parent_uid在train/dev/test之间没有交叉，但这不能替代真实的场次标识。

**为什么必须保留pending状态：**

因为未经人工确认的候选样本不能直接作为已校对的测试答案。

应先听音、核对并确认转写，再按照项目规范更新状态。

本模块核心结论：

**测试集的抽样规则应当预先确定、可复现，并且独立于模型测试结果；抽样完成只是人工校对的起点，并不意味着候选样本已经verified。**

## 2. 人工校对流程

如何播放音频：
使用soundfile读取音频，通过IPython.display.Audio在Jupyter Notebook中播放。
调用show_candidate(rank)查看指定候选样本，并完整播放对应音频。对听不清的部分可以重复播放，但不能根据上下文猜测答案。

source_text 的作用：
保存原始Common Voice数据集中已有的转写文本，它是待校对的原始参考文本，不代表已经经过本项目的人工验证。

raw_text 的作用：
记录根据实际音频人工核对后的原始转写，如果原始转写正确，则填写经听音确认的文本。如果原始转写存在明确错误，则根据音频修正。如果存在无法确认的内容，应保留不确定记录，不能把猜测当作文本。

为什么不查看模型预测结果：
避免人工标注受到模型输出的影响，也避免根据模型识别错误决定是否选择或保留样本。
人工标注应以音频证据为依据，而不是以模型预测为依据。

## 3. 标注状态

pending：
尚未完成本项目的人工听音校对，新创建时候选样本初始状态为pending

verified：
已经完整听音，并且能够确认转写内容。

needs_review：
已经尝试听音校对，但仍然存在无法确认的词语、片段或其他需要复核的问题。
不能为了凑足verified数量而猜测答案

uncertain_span 的作用：
单独记录无法确定的词语、时间位置或片段，以及相应的不确定原因。

## 5. 当前理解

- 为什么不能自动把 source_text 复制到 raw_text 并标记 verified：
因为source_text是原数据集提供的转写，并没有经过本项目的人工听音确认。自动复制不能发现错字、漏字和无法辨认的内容，也不能证明标注已经完成。

- 为什么不能根据上下文猜测听不清的词：
因为ASR测试集需要尽可能可靠的真实转写。根据语义猜测可能引入错误参考答案，进而影响模型评估的准确性和可信度。对无法确认的内容，应保留不确定状态。

- 为什么要保留原始转写和人工校对后的转写：
source_text保留数据集原始转写，raw_text保留人工校对结果。两者分开可以追踪人工修改，检查原始标注错误，并提高数据处理的可追溯性。后续用于评分归一化的score_text也应与raw_text分开保存。

- 本次测试集人工校对如何避免选择偏差：
在人工校对及模型测试之前，预先确定候选范围、随机种子与抽样顺序。不根据模型预测结果或识别错误重新选择样本。对已选样本按统一规则完整听音、记录问题并更新状态。
