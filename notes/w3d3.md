# W3D3 模块1：Causal Mask 与 Padding Mask

## 1.1 Mask加在哪里

Scaled Dot-Product Attention：

\[
Attention(Q,K,V)
=
softmax
\left(
\frac{QK^T}{\sqrt{d_k}}
\right)V
\]

Mask应该加在：

> scores->softmax之前

基本流程：

```text
QKᵀ
↓
scaling
↓
Mask
↓
softmax
↓
weights
↓
V加权
```

---

## 1.2 Mask的本质

对于不允许被访问的位置，将score设为：

> -∞

经过softmax后，该位置weight：

> 0

因此Mask控制：

> 当前Query被允许访问哪些Keys

---

## 1.3 Causal Mask

作用：

> 防止当前位置读取未来token的信息，保证自回归因果性

对于Query位置i：

```text
允许访问：
[:i]

禁止访问：
[i:end]
```

矩阵大致形状：

```text
[
 [1,0,0,0],
 [1,1,0,0],
 [1,1,1,0],
 [1,1,1,1]
]
```

---

## 1.4 Padding Mask

作用：

> 防止为了batch补齐而加入的PAD位置参与Attention计算

为什么不能让padding参与attention：

> PAD并不携带真是序列信息，如果Query可以给PAD Key分配权重，那么PAD对应的Value就会参与加权求和，从而污染Attention输出。

Padding mask主要屏蔽：

> Key/Value一侧

---

## 1.5 两种Mask区别

Causal Mask依据：

> 序列中的相对位置

Padding Mask依据：

> 每个样本的真实长度/ PAD位置

二者能否同时存在：

> 可以

---

## 1.6 Mask Shape

假设：

```text
scores shape =
(B,T_q,T_k)
```

Causal mask常见基础shape：

> (T,T)

Padding valid mask常见shape：

> (B,T_k)

通过broadcast后：

> (B,T_q,T_k)

---

## 1.7 全Mask行

如果某个Query对应所有Keys都被mask：

```text
scores =
[-inf,-inf,...]
```

softmax可能得到：

> NaN

因此需要：

> 显式检测全mask行，不能让它悄悄经过普通softmax产生NaN。

---

## 1.8 本模块核心结论

> Mask通过在softmax之前屏蔽无效scores来控制Query允许读取哪些Keys；Causal Mask阻止未来信息流向过去，Padding Mask组织PAD参与信息聚合，而全Mask行必须显示处理以避免softmax产生NaN


# W3D3 模块2：Causal / Padding Mask实现

## 2.1 Causal Mask

函数：

```python
def make_causal_mask(...):
    ...
```

输入：

> 序列长度T

输出shape：

> (T,T)

True表示：

> 当前Query允许访问该Key

---

## 2.2 Padding Mask

函数：

```python
def make_padding_mask(...):
    ...
```

输入：

> lengths：每个batch样本的真实序列长度

输出shape：

> (B,T_k)

True表示：

> 对应位置是真实token，可以作为Key被访问

---

## 2.3 Combined Mask

```python
combined_mask =
causal_mask.unsqueeze(0) & padding_mask.unsqueeze(1)
```

含义：

> 某个Key只有同时满足“不是未来位置”和“不是PAD”时，当前Query才允许访问。

---

## 2.4 Attention应用Mask

```python
scores =
(
    Q
    @ K.transpose(-2, -1)
)

scores =
scores.masked_fill(
    ~valid_mask,
    float("-inf),
)
```

为什么在softmax之前：

> 希望无效Key最终的attention weight严格变成0，同时保持有效位置之间正常的softmax归一化关系。

---

## 2.5 全Mask行

检测：

```python
valid_rows =
valid_mask.any(dim=-1,keepdim=True)
```

全mask行表示：

> 当前Query对应的所有Keys均不可访问。

处理策略：

> 先将对应scores全部置0变为均匀分布，求完weights后再将weights置零

---

## 2.6 Softmax与安全处理

```python
safe_scores =
torch.where(valid_rows,masked_scores,torch.zeros_like(masked_scores))

weights =
torch.softmax(
    safe_scores,
    dim=-1,
)
weights =
torch.where(
    valid_rows,
    weights,
    torch.zeros_like(weights),
)
```

---

## 2.7 最终行为

正常行：

> 被mask位置weight为0，其余有效位置正常softmax并且权重和约等于1。

全mask行：

> 全为0

---

## 2.8 本模块核心结论

> Causal Mask和Padding Mask最终都转化为“哪些Query-Key连接有效”的bool矩阵，在softmax之前将无效score设为-inf；对于全mask行，则需要在softmax之前和之后显式安全处理，使最终weights/output为0并避免NaN。


# W3D3 模块3：Causal Attention行为测试

## 3.1 测试目标

Causal Attention必须满足：

> 防止Query访问未来token的信息，即对应的weights位置应当为0

因此如果只修改：

> 未来部分

那么此前位置：

> output不变

---

## 3.2 测试输入

固定：

```text
seed = 42
B = 2
T = 4
d = 8
```

构造：

```python
x = torch.randn(B,T,d)
```

在self-attention测试中：

```text
Q = x
K = x
V = x
```

---

## 3.3 修改未来位置

假设：

```text
split = 3
```

表示：

> 从split往后的部分进行修改

修改：

```python
x_changed = x.clone()

x_changed[:, split:, :] = x_changed[:,split:,:]*100 + 50
```

不修改：

> 0,1,2

---

## 3.4 两次Attention

修改前：

```python
output_before, _ =
dot_product_attention(x,x,x,True,causal_mask)
```

修改后：

```python
output_after, _ =
dot_product_attention(x_changed,x_changed,x_changed,True,causal_mask)
```

两次必须使用：

> 完全相同的causal mask和Attention配置，唯一变化的是未来token内容

---

## 3.5 核心断言

```python
assert torch.allclose(
    x[:,:split,:],
    x_changed[:,:split,:],
    atol=1e-6,
)
```

这条断言验证：

> 实验确实没有修改过去输入

---

## 3.6 为什么不是比较整个output

不能要求：

```text
output_before == output_after
```

因为：

> split及之后的位置本身的Q/K/V已经被修改，所以这些位置的output允许发生变化。

真正应该比较：

> 未来未知之前的所有输出

---

## 3.7 与Shape测试的区别

Shape测试只能说明：

> Tensor维度正确，矩阵运算能够执行。

因果行为测试能够说明：

> 未来token的变化不会传播到过去位置的output，真正验证了causal constraint

---

## 3.8 本模块核心结论

> Causal Attention的正确性不能只通过shape或mask矩阵外观判断；最关键的行为测试是人为修改未来token，并验证过去位置的Attention output完全不变，同时确认所有未来未知的attention weight严格为0。
