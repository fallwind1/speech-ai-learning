# W2D6 模块1：错分样例与错误分析

## 1.1 为什么需要错误分析

accuracy只能告诉我：

> 模型预测总体上错了多少

错误分析还能告诉我：

> 真实类别是什么而模型预测为什么；模型有多自信；图片本身是否模糊；错误有没有共同规律

---

## 1.2 什么叫错分样例

对于一个样本：

```text
真实标签：
a

模型预测：
b
```

如果：

> a != b

则它属于错分样例。

---

## 1.3 如何得到模型预测

模型输出：

```python
logits = model(images)
```

shape：

> (64,10)

预测类别：

```python
preds = logits.argmax(dim=1)
```

原因：

> 利用CEloss计算损失，在单标签多分类中，即计算真实类别的NLL，最大logit所在的位置就是模型预测类别。

---

## 1.4 如何找到错分样本

判断：

```python
wrong_mask = preds != labels
```

表示：

> 返回值为BoolTensor，得到当前batch中的错误位置。

---

## 1.5 错分表需要记录什么

|字段|含义|
|---|---|
|sample_id|样本编号，用于定位样本|
|true_label|真实类别|
|pred_label|预测类别|
|confidence|自信度|
|observation|观察现象|

---

## 1.6 Confidence 的意义

confidence：

> 模型预测为该类别的自信程度

计算：

```python
probs = torch.softmax(logits,dim=1)

confidence = probs.max(dim=1).values
```

如果：

```text
true=5
pred=3
confidence=0.95
```

说明：

> 模型高置信度误判

---

## 1.7 错误分析关注什么

观察5个错分样例时主要分析：

1. 真实类别和预测类别
2. 模型信心
3. 图片是否有明显视觉特征
4. 错误有没有重复模式

---

## 1.8 错误分析不能得出什么结论

仅分析5个样本：

不能：

> 直接断言模型整体存在某种系统性错误，例如“模型经常把4识别成9”

可以：

> 发现值得继续检查的现象，并形成后续可以通过更多样本验证的假设。

---

## 1.9 本模块核心结论

一句话：

> 错误分析是在整体指标之后进一步查看模型具体错在哪里，通过真实标签、预测标签、置信度和样本特征寻找可能的错误模式，但少量样本只能用于发现问题和提出假设，不能直接形成总体结论。

```bash
ls
```

> CWD

> 当前工作目录

> 当前工作目录


```text

```

## 2.7 `.` 和 `..`

```text
.
```

表示：

> 当前目录

```text
..
```

表示：

> 当前目录的父目录

例如：

```bash
cd ..
```

表示：

> 进入当前目录的父目录

---

## 2.8 路径与Python脚本

运行：

```bash

```

此时脚本中的：

```python
Path("data")
```

通常相对于：

> 启动python时的当前工作目录cwd

而不是一定相对于：

> train.py文件所在的src目录及

---

## 2.9 本模块核心结论

一句话：

> Linux路径问题的核心是先明确当前工作目录cwd；绝对路径不依赖cwd，而相对路径依赖cwd，因此同一个Python脚本从不同目录启动时，相对路径可能指向不同位置。


# W2D6 模块3：进程与日志重定向

## 3.1 什么是进程

程序：

> 硬盘上的代码文件

进程：

> 正在运行的程序实例

运行：

```bash
python train.py
```

会：

> 操作系统创建一个正在运行的实例。

---

## 3.2 前台运行

```bash
python train.py
```

特点：

> 程序会在当前终端前台运行。

此时终端：

> 通常正在被这个训练任务占用，直到训练完成

---

## 3.3 后台运行

命令：

```bash
python train.py &
```

其中：

```text
&
```

表示：

> 将命令放到后台运行

---

## 3.4 查看进程

```bash
ps
```

作用：

> 可以查看当前shell相关进程

常见：

```bash
ps aux
```

作用：

> 显示大量系统进程

查找Python训练：

```bash
ps aux | grep python
```
|表示：管道，将前一个命令的输出作为后一个命令的输入。
---

## 3.5 标准输出重定向

```bash
python train.py > train.log
```

其中：

```text
>
```

表示：

> 把程序原本打印到终端的标准输出写入train.log

---

## 3.6 `>` 和 `>>`

```text
>
```

表示：

> 覆盖写入

```text
>>
```

表示：

> 追加写入

---

## 3.7 stderr

标准输出：

> stdout

标准错误：

> stderr

命令：

```bash
python train.py > train.log 2>&1
```

含义：

> 1->stdout 2->stderr，表示把stderr也重定向到stdout当前所在的位置。

---

## 3.8 查看日志

查看全部：

```bash
cat train.log
```
适合：
日志文件较短，希望一次查看全部内容。

查看最后几行：

```bash
tail train.log
```
适合：
日志较长，只关心最近输出。

持续查看：

```bash
tail -f train.log
```
适合：
程序仍在运行，希望持续观察最新训练日志。

---

## 3.9 本模块核心结论

一句话：

> Linux训练任务本质上是一个进程；通过后台运行、PID、管道和日志重定向，可以在不持续占用终端的情况下管理训练任务，并把正常输出和错误信息保存下来供后续检查。


# W2D6 模块4：脚本路径问题

## 4.1 问题来源

假设项目：

```text
speech-ai-learning/
├── data/
├── results/
└── src/
    └── train.py
```

代码：

```python
Path("data")
```

如果从项目根目录运行：

```bash
python src/train.py
```

路径指向：

> speech-ai-learning/data

如果从 `src` 目录运行：

```bash
python train.py
```

路径指向：

> speech-ai-learning/src/data

原因：

> Path("data")是相对路径，而相对路径依赖当前工作目录cwd

---

## 4.2 `Path.cwd()`

代码：

```python
Path.cwd()
```

作用：

> 表示当前工作目录

它表示：

> 当前工作目录

---

## 4.3 `__file__`

代码：

```python
__file__
```

表示：

> 当前这个Python文件本身的位置

与 CWD 的区别：

> cwd表示的是当前工作目录，程序从哪启动，例如：python src/train.py，则cwd=/speech-ai-learning，而__file__则为/speech-ai-learning/src/train.py。

---

## 4.4 `Path(__file__).resolve()`

代码：

```python
Path(__file__).resolve()
```

表示：

> 得到当前脚本文件的绝对路径

例如：

```text
/home/yf/speech-ai-learning/src/train.py
```

与__file__的区别：
> __file__返回的是字符串类型，而Path(__file__).resolve()返回的是Path对象，且默认不报错等，但均为绝对路径（在3.9+版本的Python中）

---

## 4.5 `.parent`

```python
Path(__file__).resolve().parent
```

表示：

> 当前脚本所在目录

再 `.parent`：

```python
Path(__file__).resolve().parent.parent
```

表示：

> 项目根目录

---

## 4.6 项目根目录

推荐：

```python
PROJECT_ROOT = Path(__file__).resolve.parent.parent
```

如果 `train.py` 在：

```text
speech-ai-learning/src/train.py
```

则 `PROJECT_ROOT` 应该指向：

> 项目根目录speech-ai-learning

---

## 4.7 稳定构造路径

数据：

```python
DATA_DIR = PROJECT_ROOT / "data"
```

结果：

```python
RESULTS_DIR = PROJECT_ROOT / "results"
```

日志：

```python
LOGS_DIR = PROJECT_ROOT / "logs"
```

这样做的好处：

> 所有路径都从项目根目录PROJECT_ROOT推导

---

## 4.8 为什么比 `Path("data")` 更稳

`Path("data")`：

> 依赖相对路径，可能导致出现路径错误

`PROJECT_ROOT / "data"`：

> 不依赖相对路径，不怕更换启动目录

mkdir(parents=True, exist_ok=True)：
> parents=True，表示：如果上一级目录不存在，也一起创建
> exist_ok=True，表示：如果目录已经存在，不报错

---

## 4.9 本模块核心结论

一句话：

> Python相对路径默认依赖当前工作目录，而 __file__ 描述脚本本身的位置；训练工程中可以先通过 Path(__file__).resolve() 确定项目根目录，再统一构造 data、results、logs 等路径，使脚本不依赖启动位置。


# W2D6 模块5：配置管理与命令行启动

## 5.1 为什么不应该把超参数散落在代码里

例如：

```python
lr = 0.1
batch_size = 64
epochs = 20
```

问题：

> 超参数散落在代码的不同位置，如果需要修改要去代码不同位置修改，容易遗漏

更好的方式：

> 集中配置用CONFIG，然后训练代码统一读取

---

## 5.2 argparse 的作用

导入：

```python
import argparse
```

作用：

> 读取用户启动程序时输入的命令行参数。

---

## 5.3 ArgumentParser

```python
parser = argparse.ArgumentParser()
```

作用：

> 创建一个命令行参数解析器

---

## 5.4 add_argument

例如：

```python
parser.add_argument(
    "--lr",
    type=float,
    default=0.1
)
```

其中：

```text
--lr:
命令行参数名称，因此可以python train.py --lr 0.01

type=float:
告诉argparse：把用户输入转换成浮点数

default=0.1:
如果用户没有提供--lr，自动使用0.1
```

---

## 5.5 parse_args()

```python
args = parser.parse_args()
```

作用：

> 读取python train.py后面的命令行内容

读取：

```python
lr = --lr 0.01 \

batch_size = --batch-size 128 \

epochs = --epochs 50
```

---

## 5.6 命令行覆盖默认值

代码：

```python
parser.add_argument(
    "--lr",
    type=float,
    default=0.1
)
```

运行：

```bash
python train.py --lr 0.01
```

最终：

```text
args.lr =
0.01
```

如果不写：

```bash
python train.py
```

最终：

```text
args.lr =
0.1
```

---

## 5.7 配置与命令行关系

推荐流程：

```text
命令行参数
↓
argparse
↓
args
↓
CONFIG
↓
训练代码
```

优点：

> 代码职责清晰，args是用户从命令行输入的参数，config还包含这次完整实验实际使用的配置，非命令行传入的内容。

---

## 5.8 从命令行启动

示例：

```bash
python src/train.py \
    --lr 0.01 \
    --batch-size 64 \
    --epochs 20
```

作用：

> 从命令行传入参数

---

## 5.9 本模块核心结论

一句话：

> argparse让训练超参数可以从命令行传入，再统一整理到config中，使训练代码无需为了不同实验反复修改源码，并为后续云服务器上的可复现实验启动打下基础。
