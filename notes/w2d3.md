# W2D3 MLP 分类训练

## 1. MLP、Flatten、Linear 与 ReLU

### 1.1 本次 MLP 结构

本次两层 MLP：

```text
输入 images：
(B,1,28,28)

↓ Flatten

(B,784)

↓ Linear(784 → 128)

(B,128)

↓ ReLU

(B,128)

↓ Linear(128 → 10)

(B,10)
```

最终输出称为：

> logits

---

### 1.2 Flatten

MNIST 一个 batch：

```text
images.shape =
(1,28,28)
```

`nn.Flatten()` 的作用：

> 将(1,28,28)展开为(784,)便于输入线性层

Flatten 后：

```text
shape =
(B,784)
```

其中：

```text
784 =
将每个sample的图像维度1*28*28变成的784个连续特征
```

需要保留的维度：

> batch-size

---

### 1.3 第一层 Linear

```python
nn.Linear(784, 128)
```

表示：

```text
in_features =
784

out_features =
128
```

输入：

```text
(B, 784)
```

输出：

```text
(B, 128)
```

这一层完成的数学运算：

\[
\text{output} = xW^T+b
\]

其中模型需要学习的参数：

> weight和bias

---

### 1.4 ReLU

ReLU：

\[
\operatorname{ReLU}(x)
=
max(0,x)
\]

它的作用：

> 引入非线性变换

经过 ReLU：

```text
shape 是否改变：
没有
```

为什么 Linear 层之间需要非线性激活：

> 如果均为Linear层的话，不论通过多少层Linear层，本质上仍可以写为一个Linear层，本质上仍然是一个Linear变换，没有增加非线性表达的能力。

---

### 1.5 输出层

```python
nn.Linear(128, 10)
```

其中：

```text
128 →
hidden features

10 →
out features
```

输出：

```text
logits.shape =
(64,10)
```

每一个样本为什么有 10 个 logits：

> 因为有10个classes，希望得到10个类别分数

最后一层后面是否手动添加 Softmax：

> 不需要

原因：

> CE自带logsoftmax

---

### 1.6 PyTorch 模型

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()

        self.model = nn.Sequential(
            nn.Flatten(),
            nn.Linear(784,128),
            nn.ReLU(),
            nn.Linear(128,10),
        )

    def forward(self, x):
        return self.model(x)
```

`nn.Sequential` 的作用：

> 按照定义顺序，让Tensor依次通过其中的模块

`model(images)` 时，数据依次经过：

```text
Flatten
→ Linear(784,128)
→ ReLU
→ Linear(128,10)
```

---

### 1.7 Shape 验证

假设：

```text
batch_size = 64
```

完整 shape：

```text
(64, 1, 28, 28)
↓
(64, 784)
↓
(64,128)
↓
(64,128)
↓
(64,10)
```

最终：

```text
logits.shape =
(64,10)
```

本模块最重要的一句话：

> MLP首先通过Flatten把每张MNIST图片变成784个输入特征，再通过Linear+ReLU学习隐藏表示，最后通过输出层为每个样本生成10各类别logits。


## 2. Logits、Probability、CrossEntropyLoss 与 Prediction

### 2.1 Logits

MLP 最后一层：

```python id="o91cx2"
nn.Linear(128, 10)
```

对于：

```text id="ee3c7v"
batch_size = B
```

输出：

```text id="dsurfk"
logits.shape =
(B,10)
```

logits 表示：

> 模型对10个类别给出的原始分数

logits 是否必须满足：

```text id="c8hxxp"
0 ≤ value ≤ 1：
不需要

所有类别之和 = 1：
不需要
```

---

### 2.2 Probability

将 logits 转成概率：

```python id="py23yf"
probabilities = torch.softmax(
    logits,
    dim=1,
)
```

这里 `dim` 表示：

> 对第一个维度，即10做softmax

Softmax 后：

```text id="b9xhep"
probabilities.shape =
(64,)
```

每个样本的类别概率满足：

```text id="0owdn9"
每个值范围：
0~1

10 个类别概率之和：
1
```

---

### 2.3 Labels / Target

MNIST batch：

```text id="a3k3oy"
labels.shape =
(64,)

labels.dtype =
torch.in64
```

例如：

```text id="y3jr7b"
labels =
[7, 2, 5, ...]
```

每一个数字表示：

> 一个真实类别index

在常见单标签分类中，不需要手动转换成：

> one-hot

---

### 2.4 CrossEntropyLoss

定义：

```python id="xfkzqe"
criterion = nn.CrossEntropyLoss()
```

计算：

```python id="nbwd8r"
loss = criterion(
    logits,
    labels,
)
```

输入 shape：

```text id="j383pe"
logits.shape =
(64,10)

labels.shape =
(64,)
```

输出：

```text id="2wphgw"
loss.shape =
torch.Size([])标量
```

训练时为什么不先手动执行 Softmax：

> 因为CE在概念上包含了LogSoftmax

---

### 2.5 CrossEntropy 的直觉

对于某一个样本：

```text id="4yeib5"
真实类别 = 7
```

CrossEntropy 主要关注：

> NLL

如果模型给真实类别的概率：

```text id="m7axp3"
越来越高
↓
loss 降低

越来越低
↓
loss 升高
```

单标签分类中，可以直观理解为：

\[
CE = -\log P(y_{\text{true}}\mid x)
\]

---

### 2.6 Predicted Class

预测类别可以写：

```python id="re992w"
pred = logits.argmax(
    dim=1
)
```

如果：

```text id="461dw1"
logits.shape = (64, 10)
```

那么：

```text id="ebfju7"
pred.shape =
(64,)
```

`argmax` 返回：

> 类别分数最大值对应的索引

为什么预测类别时通常不必先执行 Softmax：

> softmax不会改变大小关系，所以不需要用softmax

---

### 2.7 完整关系

```text id="6xkfg6"
images
↓
MLP
↓
logits
├───────────────┐
↓               ↓
CrossEntropy    Softmax
↓               ↓
loss           prob
                ↓
                argmax
                ↓
                pred
```

本模块最重要的区分：

```text id="684osq"
logits：
模型输出的原始类别分数

probabilities：
logits 经过 Softmax 后得到的类别概率分布。

labels：
每个样本对应的真实类别 index。

loss：
预测结果与真实类别之间的训练目标误差，训练时用于 backward。

prediction：
模型当前认为最可能的类别，通常由 logits.argmax(dim=1) 得到。
```


## 3. MNIST Train Loop

### 3.1 训练前需要准备的对象

模型：

```python
model = MLP()
```

损失函数：

```python
criterion = nn.CrossEntropyLoss()
```

优化器：

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.1
)
```

其中：

```text
criterion
→ 根据logits和labels计算loss

optimizer
→ 根据梯度更新model.parameters()
```

本次主要超参数：

```text
learning rate = 0.1
epochs = 25
batch size = 64
```

---

### 3.2 一个 Batch 的训练流程

完整顺序：

```text
images, labels
↓
logits
↓
loss
↓
backward
↓
step
↓
zero_grad
```

对应代码：

```python
optimizer.zero_grad()

logits = model(images)

loss = criterion(logits,labels)

loss.backward()

optimizer.step()
```

---

### 3.3 `model.train()`

训练 epoch 开始前：

```python
model.train()
```

作用：

> 把模型切换到training mode

它是否等于：

```text
“执行模型训练”
```

> 不等于
例如：
Dropout:
训练模式 → 随机丢弃
eval模式 → 不丢弃

BatchNorm:
训练模式 → 使用当前batch统计量
eval模式 → 使用保存的统计量

真正使模型参数发生更新的是：

> loss.backward() + optimizer.step()

---

### 3.4 `optimizer.zero_grad()`

作用：

> 清空上一step的梯度

为什么每个 batch 都需要调用：

> 因为grad不会自动覆盖而是累计

如果不调用：

> 当前batch的梯度会与上一batch的累加

---

### 3.5 Forward 与 Loss

Forward：

```python
logits = model(images)
```

shape：

```text
images.shape =
(64,1,28,28)

logits.shape =
(64,10)
```

Loss：

```python
loss = criterion(
    logits,
    labels,
)
```

其中：

```text
logits →
(64,10)

labels →
(64,)

loss →
torch.Size([])
```

---

### 3.6 Backward 与 Step

```python
loss.backward()
```

作用：

> 反向传播计算梯度

计算结果主要保存在：

> 计算图中

```python
optimizer.step()
```

作用：

> 根据grad更新参数

两者的区别：

> 一个更新参数，一个计算梯度

---

### 3.7 一个 Epoch

训练结构：

```python
for images, labels in train_loader:
    ...
```

一次循环：

> 一个batch

整个 `for` 循环完成：

> 全部数据

因此：

```text
batch
≈ 25

epoch
= 5
```

---

### 3.8 记录 Train Loss

每个 batch：

```python
batch_loss = loss.item()
```

`.item()` 的作用：

> 取出单个元素的数值

为了记录整个 epoch 的平均训练 loss：

```python
total_loss += loss.item() * batch_size()

total_samples += batch_size
```

最终：

```python
average_train_loss = total_loss / total_samples
```

为什么不能把带计算图的 `loss` Tensor 一直保存下来：

> 占用额外内存，后续绘图需要数值而不是Tensor

---

### 3.9 检查 Loss 是否有限

可以检查：

```python
if not torch.isfinite(loss):
    raise RuntimeError("Non-finite loss")
```

有限 loss 表示：

> 有限数值

`NaN` / `inf` 通常说明：

> 模型训练数值loss溢出，应当停止

---

### 3.10 Train Loop 核心总结

一个 batch：

```text
zero_grad
→ forward
→ CrossEntropyLoss
→ backward
→ optimizer.step
```

一个 epoch：

```text
让所有train batches依次完成上述训练流程一次
```

本模块最重要的一句话：

> Mini-batch训练本质上就是DataLoader不断提供(images, labels)，模型计算logits和loss，通过backward得到梯度，再由optimizer.step()更新参数，并重复这一过程直到遍历完整个训练集。


## 模块4：Validation Loop

## 4.1 为什么需要 Validation

训练集：

> 用于学习模型参数，通过 loss.backward() 和 optimizer.step() 更新模型。

Validation：

> 用于评估模型在未参与参数更新的数据上的表现，观察模型泛化能力。

Validation 是否更新模型参数：

> 不更新

---

## 4.2 model.train() 与 model.eval()

### model.train()

作用：

> 将模型切换到训练模式

主要影响：

> Dropout、Batchnorm

---

### model.eval()

作用：

> 将模型切换到评估模式

主要影响：

> Dropout关闭随机丢弃、Batchnorm使用固定统计量

---

二者关系：

```text
model.train()
=
训练模式下运行模型

model.eval()
=
评估模式下运行模型
```

注意：

```text
model.eval()
是否停止梯度计算：

不会
```

原因：

> with torch.no_grad()停止梯度计算

---

## 4.3 torch.no_grad()

代码：

```python
with torch.no_grad():
    logits = model(images)
    loss = criterion(
        logits,
        labels
    )
```

作用：

> 告诉PyTorch不需要记录计算图，不计算梯度。

它影响：

> 梯度计算

它是否改变模型模式：

> 不改变

区别：

```text
model.eval()
负责：
改变模型行为

torch.no_grad()
负责：
关闭梯度计算
```

---

## 4.4 Validation Loop 流程

完整流程：

```text
model.eval()
↓
**torch.no_grad()**
↓
forward计算 logits
↓
计算 loss / accuracy
```

对应代码：

```python
model.eval()

with torch.no_grad():
    for images, labels in val_loader:
        logits = model(images)

        loss = criterion(logits,labels)
```

验证阶段没有：

```python
loss.backward()
optimizer.step()
```

原因：

> 不需要梯度计算和更新参数

---

## 4.5 Validation Loss

训练阶段：

```python
loss.backward()
```

验证阶段：

是否需要：

> 不需要

原因：

> 不需要梯度计算

Validation loss 用途：

> 用于评估模型

---

## 4.6 Train / Validation 对比

| |Train|Validation|
|-|-|-|
|目的|学习参数|评价模型|
|model状态|train()|eval()|
|记录梯度|需要|不需要|
|no_grad|不用|使用|
|backward|需要|不用|
|optimizer.step|需要|不用|

---

## 4.7 torch.no_grad() 的必要性

如果验证时不使用：

```python
with torch.no_grad():
```

会：

> 计算梯度

可能导致：

> 使用optimizer.step()，模型参数改变

使用后：

> validation 不再是独立评价，而变成训练的一部分。

---

## 4.8 完整关系

```text
Train:

model.train()
↓
forward
↓
loss
↓
backward
↓
optimizer.step()


Validation:

model.eval()
↓
torch.no_grad()
↓
forward
↓
loss / metric记录
```

本模块最重要的一句话：

> model.train()和model.eval()控制模型行为模式，而torch.no_grad()控制是否记录梯度。训练需要梯度并更新参数，验证只需要评估结果，因此使用eval+no_grad()，并且不执行backward和optimizer.step()
