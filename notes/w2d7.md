## 1.7 梯度累积

PyTorch默认：

> 将上一轮梯度与这一轮累加

如果连续两个batch都执行：

```python

```

但没有：

```python

```

第二个batch参数中的梯度大致变成：

> 两轮梯度之和

因此正常训练通常需要：

> optimizer.zero_grad()

## 2.2 backward

执行：

```python
loss.backward()
```

作用：

> 通过反向传播计算loss对参数的梯度

计算时使用的核心数学规则：

> 链式法则

它从哪里开始：

> 最终的标量loss

最终主要计算：

> loss对模型参数的偏导数

---

## 2.3 梯度存在哪里

假设参数：

```python
weight
```

执行：

```python
loss.backward()
```

后梯度通常存放在：

```python
weight.grad
```

其数学含义：

> $[\frac{\partial loss}{\partial weight}]$

---

## 2.4 backward 是否更新参数

`loss.backward()`：

> 只负责计算梯度并写入参数的.grad，不会直接修改参数值

`optimizer.step()`：

> 根据当前参数的.grad和优化算法规则真正更新模型参数

二者关系：

```text
backward计算梯度
↓
optimizer利用梯度更新参数
```

---

## 2.5 zero_grad

```python
optimizer.zero_grad()
```

作用：

> 清空优化器所管理参数中上一轮残留的梯度。

为什么普通训练通常每个batch都需要它：

> 因为 PyTorch 默认会累积梯度。如果不清空，上一个batch的梯度会继续留在 .grad 中并与下一个batch的梯度相加。

---

## 2.6 梯度累积

假设：

```text
batch1梯度 = g1
batch2梯度 = g2
```

如果两个batch之间没有清梯度：

```text
batch1 backward后：
grad = g1

batch2 backward后：
grad = g1+g2
```

原因：

> PyTorch 默认不会在每次 backward 前自动清空 .grad，新计算出的梯度会累加到已有梯度上。

---

## 2.7 正常minibatch训练

一般顺序：

```text
zero_grad
↓
forward
↓
loss
↓
backward
↓
step
```

每一步作用：

- `zero_grad()`：清空上一batch残留梯度；
- forward：根据输入和当前参数得到模型预测，并建立计算图；
- loss：衡量预测结果与真实标签的差异；
- backward：利用计算图和链式法则计算参数梯度；
- step：利用梯度真正更新模型参数。

---

## 2.8 故意梯度累积

梯度累积并不一定是错误。

有些训练会故意：

> 连续对多个小batch执行 backward，让梯度累积，再统一执行一次 optimizer.step()。

此时不能：

> 每个小batch都立即把梯度清空，否则就无法形成累积。

而应该：

> 在计划好的若干个小batch之间保留梯度，达到指定累积次数后再进行参数更新和清梯度。

---

## 2.9 detach 与 no_grad

`detach()`：

> 针对某个 Tensor，将其从当前计算图中分离，之后的梯度不会再通过这个连接向前传播。detach得到的Tensor通常与原Tensor共享底层数据，不能简单理解为一份完全独立的数据副本。

`torch.no_grad()`：

> 在整个代码区域内关闭 autograd 的梯度记录。

一句话：

> forward建立计算关系，backward从loss出发利用链式法则计算并累积参数梯度，optimizer.step使用这些梯度更新参数；普通minibatch训练他用过zero_grad避免不同batch意外累积，而有计划的梯度累积则可以作为一种训练策略
