# W4D7：复盘与数据闸门

## 1. 数据闸门

### 为什么需要数据闸门

数据在进入模型训练之前需要检查：数据的来源、许可、划分和质量，避免不符合要求的数据进入后续实验

数据闸门主要检查：

- 数据来自哪里
- license是什么
- 是否允许用于模型训练
- 是否允许云端处理
- 是否允许再分发
- 是否存在敏感信息
- train/dev/test是否合理
- train/dev/test是否存在speaker/session交叉
- 数据是否存在明显偏置

### “可以使用”与“可以公开/上传”的区别

例如：
某个数据集可能：

text
允许本地训练：√
允许本地保存：√
允许云端处理：×
允许公开原始音频：×
允许再分发：×

## 3. Git 数据安全

### 为什么不能把原始音频直接提交到 Git
原始音频可能受到数据许可限制，也可能包含说话人的隐私信息。

### 为什么 metadata 不等于“所有信息都可以公开”
metadata中可能包含敏感信息，例如：
敏感转写文本；
个人身份信息；
其他隐私信息。

### 不应该进入 Git 的内容

- 未授权的原始音频
- 不允许公开的wav/mp3
- 敏感转写
- 个人隐私信息
- API Token
- 密码
- 授权凭证
- 其他不允许公开的数据

### 可以提交的内容

- 数据处理代码
- 测试代码
- 数据统计结果
- README
- 不包含敏感信息的实验配置等

## 4. Git 检查流程

提交前的基本流程：

text
修改文件
↓
git status
↓
git add
↓
git diff --cached
↓
检查暂存区
↓
git commit

git status 的作用：查看当前工作区和暂存区的状态，知道哪些文件被修改、哪些文件准备提交。
git diff --cached 的作用：查看当前暂存区中具体准备进入下一次 commit 的内容。
git ls-files 的作用：查看 Git 当前已经跟踪的 mp3/wav 文件。
git check-ignore -v 的作用：检查某个文件是否被 .gitignore 忽略，以及是哪一条规则生效。
为什么 .gitignore 不能保证已经 commit 的文件自动消失：
.gitignore不是历史数据删除工具，只能针对未被Git跟踪的文件
