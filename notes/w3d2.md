# W3D2 模块1：Attention Shape 与 B / T / d

## 1.1 三个基本维度

```text
B = 2
T = 4
d = 8
```

其中：

> B：Batch-size

> T：Sequence-Length

> d：Feature Dimension

可以理解为：B个样本×每个样本T个位置×每个位置d个特征

---

## 1.2 Q / K / V Shape

Self-Attention中，假设序列长度为T：

```text
Q shape =
(B,T,d)

K shape =
(B,T,d)

V shape =
(B,T,d)
```

---

## 1.3 Cross-Attention

假设：

```text
Decoder长度 = T_q
Encoder长度 = T_k
```

则：

```text
Q shape =
(B,T_q,d)

K shape =
(B,T_k,d)

V shape =
(B,T_k,d)
```

---

## 1.4 QKᵀ

原始：

```text
Q shape = (B, T_q, d_k)

K shape = (B, T_k, d_k)
```

转置：

```text
Kᵀ shape = (B, d_k, T_k)
```

相乘：

```text
QKᵀ shape = (B,T_q,T_k)
```

其中：

```text
score[b, i, j]
```

表示：

> 第b个样本里，第i个Query与第j个Key的点积匹配分数

---

## 1.5 Attention Weights

```python
weights = torch.softmax(
    scores,
    dim=-1
)
```

为什么：

> -1表示最后一个维度，也就是Keys对应的维度，将一个Query对所有Keys的scores转为权重分布

weights shape：

> (B, T_q, T_k)

每一行满足：

> 和为1

---

## 1.6 与V相乘

```text
weights shape = (B, T_q, T_k)

V shape = (B, T_k, d_v)
```

所以：

```text
output shape = (B, T_q, d_v)
```

含义：

> 每一个Query得到一个新的d_v维表示。

---

## 1.7 PyTorch核心实现

```python
scores = Q @ K.transpose(-2,-1)

scores = scores / math.sqrt(Q.size(-1))

weights = torch.softmax(scores, dim=-1)

output = weights @ V
```

---

## 1.8 本模块核心结论

一句话：

> Attention的shape主线是Q(B,T_q,d_k) 与转置后的K (B,d_k,T_k) 相乘得到scores (B,T_q,T_k)，沿Key维做softmax得到weights，再与V (B,T_k,d_v) 相乘，最终得到每个Query对应的output (B,T_q,d_v)。


# W3D2 模块2：Scaled Dot-Product Attention实现

## 2.1 函数目标

输入：

```text
Q shape = (B,T_q,d_k)
K shape = (B,T_k,d_k)
V shape = (B,T_k,d_v)
```

输出：

```text
output shape = (B,T_q,d_v)
weights shape = (B,T_q,T_k)
```

---

## 2.2 参数检查

需要保证：

```text
Q与K：
特征维度d_k相同

K与V：
序列长度T_k相同

Q/K/V：
batch-size相同
```

---

## 2.3 计算scores

```python
scores = (
    Q
    @ K.transpose(-2, -1)
)
```

shape：

> (B,T_q,T_k)

含义：

> scores中保存每个样本内，每一个Query与所有Keys之间的点积匹配分数。

---

## 2.4 Scaling

```python
d_k = Q.size(-1)

scores = (
    scores
    / math.sqrt(d_k)
)
```

作用：

> 控制Q/K点积分数的数值尺度

---

## 2.5 Softmax

```python
weights = torch.softmax(
    scores,
    dim=-1,
)
```

为什么dim=-1：

> scores的最后一个维度是T_k，即当前Query面对的所有Keys。

检查：

```python
row_sums = weights.sum(
    dim=-1
)
```

预期：

> 所有元素均为1

---

## 2.6 Value加权

```python
output = weights @ V
```

output shape：

> (B,T_q,d_v)

---

## 2.7 数值检查

需要确认：

```text
output中是否全部finite：
是

weights中是否全部finite：
是

每行weights和：
=1
```

---

## 2.8 本模块核心结论

一句话：

> Scaled Dot-Product Attention先计算Q与所有Keys的点积score，用√d_k缩放后沿Key维做softmax得到attention weights，在利用这些权重对Values进行加权求和；实现时应同时检查shape、weight行和以及输出是否存在NaN/Inf


# W3D2 模块3：有无Scaling的Attention Entropy实验

## 3.1 Attention Entropy

对于一组attention weights：

\[
p_1,p_2,\dots,p_T
\]

Entropy定义：

\[
H =
$-\sum_i p_i\log p_i$
\]

Entropy较高表示：

> Attention weights更加分散、更加接近均匀分布，没有把绝大多数权重集中在极少数Key上。

Entropy较低表示：

> Attention weights更加尖锐，注意力主要集中在少数Key上。

---

## 3.2 两种Attention

Scaled：

```text
scores =
QKᵀ / √d_k
```

Unscaled：

```text
scores =
QKᵀ
```

其他条件：

> Q/K/V、seed、B、T、d等全部保持一致，只改变是否执行scaling

---

## 3.3 实验变量

固定：

```text
seed = 42
B = 2
T = 4 
d = 64
```

唯一改变：

> 是否将QKᵀ除以√d_k。

---

## 3.4 Entropy实现

```python
def attention_entropy(weights):
    entropy = -(weights * torch.log(weights)).sum(dim=-1)
    return entropy.mean()
```

为什么需要：

```text
clamp / epsilon：
因为log0在数学上没有定义，数值计算中如果weight变为0，则log0->-∞，可能进一步产生NaN
```

---

## 3.5 实验结果

| 条件 | Mean Attention Entropy |
|---|---:|
| Scaled |1.128677|
| Unscaled |0.290982|

观察：

> Scaled Attention的entropy明显高于Unscaled Attention

---

## 3.6 为什么产生差异

```text
没有scaling
↓
Q、K点积由较多维度累加
↓
不同score之间的数值差异进入softmax
↓
softmax更加尖锐/容易饱和
↓
entropy降低
```

加入scaling：

```text
÷ √d_k
↓
控制score的数值尺度
↓
softmax不过度饱和
↓
entropy提高
```

---

## 3.7 本模块核心结论

> 在固定Q/K/V的单变量实验中，未进行scaling时Attention Entropy由1.1287下降到0.2910，说明QKᵀ较大的score尺度会使softmax明显更加尖锐；除以√d_k可以控制score尺度，使softmax不容易过早进入极端饱和状态。


# W3D2 模块4：Softmax数值稳定性与最终验收

## 4.1 Naive Softmax

公式：

\[
softmax(x_i)
=
\frac{e^{x_i}}
{\sum_j e^{x_j}}
]
\]

直接实现可能出现的问题：

> 当scores中存在非常大的正数时，计算 exp(score) 可能超过浮点数能够表示的范围，产生 inf。

---

## 4.2 为什么大数会出问题

假设：

```text
scores = [1000, 1001, 1002]
```

直接计算：

```text
exp(1000)
exp(1001)
exp(1002)
```

可能导致：

> 浮点数overflow，结果变成 inf。

最终可能产生：

> NaN

---

## 4.3 Stable Softmax

稳定处理：

```text
scores
↓
减去最大值max
↓
exp
↓
除以总和
```

为什么不改变softmax结果：

> 因为上下同时约去相同数，不改变最终结果

---

## 4.4 torch.softmax

实际Attention中：

```python
weights = torch.softmax(
    scores,
    dim=-1
)
```

相比手写naive softmax：

> torch.softmax使用成熟的数值实现，不需要自己直接计算 exp(scores) / sum(exp(scores))。

---

## 4.5 最终正确性检查

### Shape

```text
Q = (2,4,64)
K = (2,4,64)
V = (2,4,64)
scores = (2,4,4)
weights = (2,4,4)
output = (2,4,64)
```

### Weight Row Sum

```python
row_sums = weights.sum(
    dim=-1
)

assert torch.allclose(
    row_sums,
    torch.ones_like(row_sums),
    atol=1e-6,
)
```

预期：

> 每个Query对应的所有attention weights之和约等于1。

### Finite

```python
assert torch.isfinite(
    weights
).all()

assert torch.isfinite(
    output
).all()
```

预期：

> weights和output中的所有元素都是finite。

---

## 4.6 Scaling与Stable Softmax的区别

Scaling解决：

> Q/K点积的数值尺度会随着 (d_k) 增大而变大，使softmax输入容易过于极端、分布过早变得尖锐甚至进入饱和区域。

Stable Softmax解决：

> 当score绝对值本身非常大时，直接计算指数可能overflow并产生Inf/NaN。

二者：

> 解决的是两个不同层面的数值问题，不能互相替代

## 4.8 本日核心结论

> Scaled Dot-Product Attention通过QKᵀ计算Query-Key匹配分数，用√d_k及控制score随特征维度增长而产生的尺度问题，再沿Key维执行数值稳定的softmax得到attention weights，最后对V进行加权求和；实现时应验证Tensor shape、attention weight行和以及weights/output是否存在NaN或Inf。
